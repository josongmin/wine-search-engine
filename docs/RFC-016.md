RFC-016
Deterministic Admission Gate & Failure Semantics

**상위·정합 문서**

- `RFC-000` — Decision-boundary / Evidence-bearing 철학의 최종 closure
- `RFC-005` — `QueryPlanV1`, `threshold_profile_id`, `query_budget`, `admission_context`
- `RFC-006` — Resolver calibrated signals (`S1`, `S2`, `Δ`, `decision_confidence_c`)
- `RFC-007` — Final authority / `DecisionOutput`
- `RFC-008` — `SearchResponseV1` / `evidence_items` / `decision_snapshot`
- `RFC-009` — wrong-top1-heavy evaluation / release gate
- `RFC-014` — external contract / replay
- `RFC-015` — `DecisionSnapshot` / replay / kill switch / rollout

**충돌 시 RFC-000과 RFC-015가 우선한다.**

0. 목적

이 RFC의 목적은 하나다.

**시스템 어디에서도 “근거 없는 `resolved`”가 구조적으로 발생하지 못하게** admission boundary를 닫는다.

즉:

- identity가 유효해야 하고
- snapshot이 일치해야 하며
- evidence가 충분해야 하고
- failure reason이 단일 SSOT로 남아야 한다

1. 핵심 원칙

1.1 단일 admission authority

최종 **`decision_status = resolved`**는 **Admission Gate를 통과한 경우에만** 가능하다.

1.2 fail-closed

다음 중 하나라도 만족하지 못하면 **`resolved` 금지**:

- identity validity
- snapshot consistency
- evidence sufficiency
- policy / ambiguity gate

1.3 signal ≠ authority

resolver / ranking / retrieval은 신호를 만든다.  
**Admission Gate만** 최종 “확정 가능 여부”를 닫는다.

2. AdmissionGateInput

```
AdmissionGateInput {
  query_plan: QueryPlanV1
  resolver_result: EntityResolveResult
  ranking_signals?: SignalSet
  decision_snapshot: DecisionSnapshot

  evidence_summary: {
    identity_evidence_present: boolean
    constraint_evidence_present?: boolean
    anchor_evidence_present?: boolean
    evidence_ref_count?: int
  }

  snapshot_refs: {
    retrieval_index_version: string
    alias_projection_version?: string
    planner_version: string
    policy_rule_version: string
    threshold_profile_id: string
  }

  selected_entity?: EntityRef
}
```

`query_plan.admission_context`(RFC-005)는 어떤 종류의 sealing·evidence가 **필요한지**를 표면화한다 — Planner는 `resolved`를 확정하지 않는다.

3. EntityRef sealing

```
EntityRef {
  entity_id: EntityId
  identity_signature: string
  snapshot_ref: string
}
```

규칙:

- Resolver / Decision / Response 경계에서 entity는 **문자열 label만으로** 다루지 않고 **`EntityRef`**로 다룬다 (RFC-001 §1.5).
- flatten alias / projection field만으로 **`EntityRef`를 새로 구성하면 안 된다**.
- **`EntityRef` 없는 `resolved`는 금지.**

4. Snapshot consistency

다음을 반드시 만족해야 한다.

- `snapshot_refs.retrieval_index_version` == `decision_snapshot.index_versions.retrieval_index_version`
- `snapshot_refs.planner_version` == `decision_snapshot.planner_version`
- `snapshot_refs.policy_rule_version` == `decision_snapshot.policy_rule_version`
- `snapshot_refs.threshold_profile_id` == `decision_snapshot.threshold_profile_id`

불일치 시:

- `decision_status = failed`
- `next_action = fail` (또는 정책에 따라 `hybrid_search` — 단 **`resolved` 금지**)
- `failure_reason = SNAPSHOT_MISMATCH`

5. Evidence sufficiency gate

`decision_status == resolved`를 허용하려면 최소 조건:

| 조건 | 필수 evidence |
|------|----------------|
| 항상 | identity evidence |
| constraints 존재 | constraint evidence |
| anchor 존재 (`admission_context`·route 기준) | anchor evidence |

semantic / popularity / dense score만으로 **`resolved` 금지.**

6. FailureReason SSOT

```
enum FailureReason {
  SNAPSHOT_MISMATCH
  IDENTITY_REFERENCE_MISSING
  IDENTITY_SEAL_VIOLATION
  EVIDENCE_INSUFFICIENT
  HARD_CONSTRAINT_VIOLATION
  AMBIGUITY_BLOCKED
  POLICY_BLOCKED
  BLOCKING_MISS
  INTERNAL_INCONSISTENCY
}
```

모든 하위 RFC는 **임의 문자열 reason**을 남발하지 말고, 이 enum을 **확장 절차**(문서 개정·버전)로만 추가한다.

7. Admission rule (의사코드)

```
if selected_entity is null and path requires exact identity:
    FAILED(IDENTITY_REFERENCE_MISSING)

elif entity ref / identity_signature check fails:
    FAILED(IDENTITY_SEAL_VIOLATION)

elif snapshot consistency check fails:
    FAILED(SNAPSHOT_MISMATCH)

elif hard constraint violated:
    FAILED(HARD_CONSTRAINT_VIOLATION)

elif ambiguity / policy blocks resolve:
    AMBIGUOUS(AMBIGUITY_BLOCKED or POLICY_BLOCKED)

elif evidence sufficiency gate fails:
    AMBIGUOUS or FAILED(EVIDENCE_INSUFFICIENT)  // 정책·route에 따라

else:
    RESOLVED
```

8. Output contract

```
AdmissionGateOutput {
  decision_status: "resolved" | "ambiguous" | "failed"
  next_action: "return_result" | "clarify" | "hybrid_search" | "fail"
  selected_entity?: EntityRef
  failure_reason?: FailureReason
  admission_trace_ref: string
}
```

최종 외부 계약은 `DecisionOutput`(RFC-007)·`EngineDecision`(RFC-008)에 흡수한다 — `failure_reason`·`admission_trace_ref` 필드로 surface.

9. Release gate alignment

새 threshold / 새 retriever / 새 overlay / 새 matcher는  
**RFC-009 release gate + RFC-015 replay / rollout gate + 본 RFC admission invariants**를 모두 통과해야 한다.

10. 금지

- evidence 없이 `resolved`
- snapshot 불일치 상태에서 replay success 주장
- flatten alias만으로 exact identity 확정
- learned score를 decision authority처럼 사용

11. 체크리스트

- [ ] `resolved`가 RFC-016을 거치지 않고 나갈 수 있는 코드 경로가 없는가
- [ ] `FailureReason`이 enum 외 난립하지 않는가
- [ ] `EntityRef` 없이 `resolved`가 가능한가 — **불가능해야 함**

한 줄 요약

**RFC-016은 “P0 네 충”을 한 번에 닫는 closure RFC다 — 근거 없는 확정을 구조적으로 막는다.**
