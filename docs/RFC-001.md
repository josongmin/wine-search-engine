RFC-001
Entity Identity Graph SSOT

**상위 문서:** `RFC-000: Wine Intelligence Engine Master Architecture.md` (동일 `docs/`) — Entity SSOT는 그 Root이며, **행동신호·bandit overlay는 이 그래프를 직접 오염시키면 안 된다** (RFC-000 §3.4).

0. 목적 (Why this exists)

이 시스템의 모든 문제는 결국 여기서 터진다.

alias 잘해도 → entity 틀리면 끝
retrieval 좋아도 → entity 붕괴되면 의미 없음
LLM 잘 붙여도 → identity 틀리면 hallucination

따라서:

Entity Identity는 전체 시스템의 Root SSOT이며, 절대 오염되면 안 된다

1. 설계 원칙 (Non-negotiable)
1.1 Logical Graph, Physical Freedom
논리 모델: Graph
구현: 자유 (RDB / KV / document / graph DB)

절대 규칙:

retrieval index는 projection이다.
identity는 source of truth다.

1.2 Identity ≠ Document

잘못된 접근:

"Opus One 2018 Napa Valley 750ml"
= 하나의 document

정답:

Wine (Opus One)
 └─ Vintage (2018)
     └─ Producer (Opus One Winery)
     └─ Region (Napa Valley)
1.3 Stable ID System

모든 entity는 불변 ID 가져야 한다.

EntityId = UUID or deterministic hash

금지:

label 기반 ID
marketplace ID 재사용
외부 catalog ID 직접 사용
1.4 Separation of Concerns

| 영역 | 역할 |
|------|------|
| Identity Graph | truth (유일한 정체성) |
| Retrieval Index | search-optimized **projection** (읽기 전용 복제) |
| Alias System (RFC-003) | surface form → entity 매핑; **flat string 금지** |
| Behavioral overlay | 검색/클라리피케이션 **위에** 얹는 가중치 — **core prior 아님** (RFC-000 §3.4) |

1.5 EntityRef sealing (runtime contract)

Identity Graph의 entity는 **런타임 경계**에서 항상 **`EntityRef`**로 참조한다 (RFC-016).

```
EntityRef {
  entity_id: EntityId
  identity_signature: string
  snapshot_ref: string
}
```

규칙:

- exact/entity route에서 **문자열 label, alias value, projection field**는 `EntityRef`를 **대체하지 못한다**.
- retrieval projection에서 읽은 문자열만으로 **새 identity를 재구성하면 안 된다**.
- **`resolved` 결과는 반드시 `EntityRef`를 통해서만** 외부에 노출된다 (RFC-007·RFC-008).

2. Entity Model (SSOT)
Entity {
  id: EntityId
  type: EntityType

  canonical_label: string
  identity_signature: string

  relations: Relations
  attributes: Attributes

  metadata: Metadata
}
2.1 EntityType
enum EntityType {
  wine
  vintage
  producer
  region
  grape
}

확장 가능:

appellation
brand
distributor (optional)
2.2 Relations
Relations {
  produced_by: EntityId        // vintage → producer (또는 wine → producer, 타입별 허용 규칙 고정)
  variant_of: EntityId         // vintage → wine (parent SKU / NV 라인)
  located_in: EntityId         // producer → region (또는 wine → region — 스키마는 한 가지로 통일)
}

핵심:

direct edge만 허용
derived relation은 runtime에서 계산
**같은 edge 이름이라도 `EntityType`에 따라 의미가 달라질 수 있음** — 문서화된 매트릭스(누가 누구를 가리키는지)를 팀 합의로 고정할 것

2.2.1 Runtime Traversal Budget

multi-hop 관계 탐색 (예: "오푸스원" → Opus One Winery → Napa Valley → 유사 region 와인)은 그래프 특성상 무한 확장될 수 있다.

**제약:**

- **max_hop:** runtime relation traversal은 **최대 2-hop**을 기본 상한으로 한다 (entity → direct relation → 1-hop neighbor). 3-hop 이상은 batch/offline에서만.
- **시간 제한:** hop 탐색은 `QueryBudget.max_latency_ms`(RFC-005 §7.6)의 **20% 이내**로 제한. 초과 시 현재까지 수집된 hop 결과로 진행.
- **캐시:** 자주 탐색되는 relation path (예: wine → producer → region)는 **materialized view / 캐시**로 유지. invalidation은 Entity Graph commit과 동기화.
- **fan-out 제한:** 단일 hop에서 fan-out이 50 이상이면 popularity/relevance 기준으로 pruning 후 진행.

2.3 Attributes (정규화 대상)
Attributes {
  grapes: string[]
  style: string
  body: float
  sweetness: float

  region: string
  price_band: string

  vintage: int
}

주의:

attribute는 identity가 아님
attribute mismatch로 entity 분리 금지
2.4 Identity Signature

**타입별로 다른 입력을 해시한다.** §3.1과 모순되면 안 된다 — **vintage 엔티티에 vintage 연도가 signature 밖에 있으면 collapse 위험**이다.

예시 (필드 선택은 제품에 맞게 조정):

- `wine`: `hash(canonical_label + producer_id + region_id [+ style line])` — **연도 제외**
- `vintage`: `hash(wine_id + vintage_year)` 또는 동등한 **연도 포함** 조합 — wine과 동일 해시 금지
- `producer` / `region`: `hash(normalized_label + parent_region_id …)`

용도:

deduplication
ingestion merge key

2.5 External identifiers (sameAs / external_ref)

LWIN, Wikidata, 마켓플레이스 SKU 등은 **identity를 대체하지 않는다.** `EntityId`는 내부 불변 ID로 유지하고, 외부 ID는 **별도 매핑 테이블** 또는 `external_ids[]`로 보관한다.

금지: 외부 catalog ID를 `EntityId`로 직접 채택 (§1.3과 동일 취지).

2.6 Provenance (권장)

필드 단위 **출처·신뢰도**를 두면 merge·충돌 해결에 유리하다 (최소: `source_system`, `asserted_at`, `trust_tier`). 상세는 ingestion RFC(RFC-002)에서 확장.
3. Entity Granularity Rules
3.1 Wine vs Vintage 분리 (중요)
케이스	처리
Opus One	wine
Opus One 2018	vintage

절대 금지:

vintage를 wine으로 합치기
wine에 vintage attribute 붙이기
3.2 Producer ≠ Wine
Château Margaux (producer)
Margaux (region)
Château Margaux 2015 (wine/vintage)

→ ambiguity 핵심 원인

3.3 Region Hierarchy
France
 └ Bordeaux
    └ Margaux

flatten 금지

3.4 NV, gift SKU, marketplace noise

- **Non-vintage (NV)** 라인은 별 `wine` 노드로 두고 vintage와 합치지 않는다 (§3.1).
- **Gift box / 750ml / import** 같은 **카탈로그 노이즈**는 identity가 아니라 **alias·catalog_noise** 측(RFC-003)에서 처리 — 제목 문자열을 canonical로 승격하지 않는다 (§6.3과 연결).

4. Identity Merge Rules (Critical)

ingestion에서 반드시 필요

4.1 Merge 조건
if identity_signature 동일
AND type 동일
→ merge 가능
4.2 Merge 금지 조건
vintage mismatch
producer mismatch
region mismatch
4.3 Conflict Resolution

우선순위:

trusted source
majority vote
manual override

4.4 Merge audit (필수에 가깝게)

모든 merge/split/override는 **감사 로그**를 남긴다 (누가, 언제, 어떤 소스 근거로, 이전/이후 `EntityId`).  
wrong-top1 사고 시 **역추적**이 가능해야 RFC-000의 eval·플라이휠(§14)과 맞는다.

4.5 Identity Graph Backup & Rollback (운영 필수)

merge/split 사고(예: 10만 entity 잘못 병합)는 downstream 전체를 오염시킨다. 복구 경로가 없으면 RFC-015 kill switch도 소용없다.

**필수:**

- **Point-in-time snapshot:** Entity Graph SSOT는 최소 **일 1회** 전체 스냅샷 + **merge/split 이벤트마다** incremental changelog.
- **Rollback procedure:** 특정 시점 또는 특정 batch job 이전 상태로 Entity Graph를 되돌릴 수 있어야 한다. `LineageRecord`(RFC-002 §9.1)의 `decision`·`timestamp`로 역추적.
- **Cascade rollback:** Entity Graph rollback 시 **Alias SSOT(RFC-003) → Projection(§5) → Retrieval Index(RFC-012)** 순서로 연쇄 재빌드. 부분 rollback(특정 entity만)도 지원 권장.
- **Recovery SLA:** 사고 인지 후 **4시간 이내** 이전 정상 상태로 복구 가능해야 한다 (팀 SLA로 구체화).
- **Drill:** 분기 1회 이상 복구 훈련 — 실제 rollback 실행·projection rebuild·검색 품질 검증까지.

5. Projection Model (for Vespa)

retrieval용 document는 이렇게 생성됨

{
  "entity_id": "...",
  "type": "vintage",

  "canonical_label": "Opus One 2018",
  "aliases_identity_safe": [...],
  "aliases_noisy_recall": [...],

  "producer": "Opus One Winery",
  "region": "Napa Valley",

  "attributes": {...}
}

핵심:

이건 복사본이다
여기서 수정 금지 — 변경은 **항상 Identity Graph에서** 하고 projection은 **재빌드**

5.1 Alias in projection

projection의 **`aliases_identity_safe` / `aliases_noisy_recall`**(RFC-012)는 **Alias SSOT(RFC-003)의 투영**이다. 타입·scope 없이 문자열만 복사하지 말 것 (RFC-000 §3.2).

5.2 Identity-strong retrieval 필드 (RFC-012 계약과 공유)

`RetrievalDocument`(RFC-012)에 실리는 아래는 **정체성·계층**에 직접 연결된다 — **프로모션·행사·마켓 노이즈 텍스트가 이 영역을 오염시키면 안 된다**:

- `canonical_label`, `entity_type`(또는 동등 필드)
- `producer`, `region`
- wine / vintage 계층을 드러내는 필드

이 필드들은 **identity-strong**이며, noisy recall 전용 필드(RFC-003 `catalog_noise_alias` 투영 등)와 **스키마·랭킹 가중에서 분리**한다.

6. Failure Modes (이 RFC가 막는 것)
6.1 Entity Collapse
여러 vintage가 하나로 합쳐짐
결과: wrong-top1 폭발
6.2 Alias Overwrite
alias가 identity를 덮어씀
6.3 Catalog Pollution
marketplace title이 canonical이 됨
6.4 Graph Break
relation 끊어짐 → mixed query 실패

6.5 Behavioral signal pollution

클릭·판매 로그로 **core merge 규칙이나 identity_signature를 흔들지 말 것** — overlay는 검색·랭킹·클라리피케이션 층에만 (RFC-000 §3.4).

7. Metrics

이 레벨에서도 평가 필요 — 최종적으로는 **wrong-resolve / wrong-top1**으로 번진다 (RFC-000 §10.7).

- entity dedup accuracy
- merge error rate
- identity collision rate (signature 충돌·중복)
- vintage correctness rate (wine/vintage 오분류율)
- merge audit coverage (감사 로그 누락률)
