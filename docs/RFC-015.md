RFC-015
Determinism, Replay, Operational Controls & Failure Containment

**상위·정합 문서**

- `RFC-000` — Decision §8, Evidence §9, Eval §10 — 본 RFC는 **운영에서 시스템을 살리는 횡단 장치**다.
- `RFC-005` — `QueryPlanV1`, **`ThresholdProfileV1` SSOT**, `SessionContext`, `QueryBudget`
- `RFC-007` — `DecisionInput`/`DecisionOutput`, **Evidence Obligation**, `decision_snapshot`
- `RFC-008` — `SearchResponseV1`에 스냅샷·counterfactual 노출
- `RFC-009` — Determinism Gate, evidence completeness metric, drift monitor, kill switch **릴리즈·모니터링**
- `RFC-010` — 학습·overlay·threshold 제안과 **promotion / kill switch** 연결
- `RFC-014` — **Replay API** 외부 계약
- `RFC-016` — **Admission Gate**; snapshot·evidence invariant, `failure_reason` — replay **false success**·§13 게이트와 정합

**충돌 시 RFC-000·RFC-007·RFC-009 우선.**

0. 목적

알고리즘 SSOT만으로는 프로덕션이 버틸 수 없다.

**embedding 교체 · 인덱스 리프레시 · threshold 튜닝 · alias overlay** 중 하나만 바뀌어도 동일 쿼리 결과가 달라질 수 있다.

이 RFC의 한 줄:

**재현 가능하고, 오염을 봉인하고, 증거 없는 확정을 막으며, 운영자가 멈출 수 있는** 계층을 정의한다.

1. 비목표

| 하지 않음 | 담당 |
|-----------|------|
| 수학적 Decision 게이트 정의 | RFC-000 §8, RFC-007 |
| typed alias SSOT | RFC-003 |
| hybrid retrieval 구현 | RFC-012 |

2. DecisionSnapshot (필수 개념)

`DecisionOutput`·`EngineDecision`·`meta`(RFC-008)에 실을 **동일 구조** — **재현·감사·A/B·리플레이**의 단위다.

```
DecisionSnapshot {
  model_versions: {
    dense_model: string
    sparse_model: string
    reranker_model?: string
  }

  index_versions: {
    retrieval_index_version: string
    alias_projection_version: string
  }

  policy_rule_version: string         // RFC-005 policy_rule_version과 정합
  threshold_profile_id: string       // RFC-005 ThresholdProfileV1.id
  planner_version: string

  feature_flags: string[]

  /** 선택 — 바이트 동일 재현이 아닌 경우 이유 */
  nondeterminism_notes?: string[]
}
```

**원칙:** 프로덕션 `/v1/search` 응답에는 **항상** `decision_snapshot`을 포함한다 (RFC-008·RFC-014). 디버그 전용이 아니다.

3. Determinism & Replay

3.1 문제

동일 `query`라도 모델·인덱스·프로파일이 바뀌면 결과가 변한다 → 디버깅·eval 회귀·고객 신뢰 붕괴.

3.2 재현 단위

재현의 최소 단위는 **`DecisionSnapshot` + 정규화된 query + `QueryPlanV1` 관련 버전**이다.  
(부동소수·GPU 비결정론은 `nondeterminism_notes`·tolerance로 문서화 — RFC-009 Determinism Gate.)

3.3 Replay API (RFC-014 SSOT)

- `POST /v1/search/replay`
- **Body:** `query`, `context`(선택), **`decision_snapshot`**(필수 — 이전 응답에서 받은 것), `options`(선택)
- **기대:** 스냅샷에 고정된 모델·인덱스·프로파일 경로로 **동일 라우팅·동일 Decision 입력**을 재구성. 바이트 단위 동일은 인프라가 지원할 때만 보장; 그렇지 않으면 **허용 오차·해시 tolerance**(RFC-009)로 검증.

3.4 효과

회귀 디버깅, A/B 정확한 비교, “deterministic under snapshot” 서술 가능.

4. Threshold & Policy Versioning (요약)

**전체 스키마는 RFC-005 `ThresholdProfileV1` SSOT.**  
Decision Layer는 항상 **`policy_rule_version` + `threshold_profile_id`** 기준으로 `T_resolve(Q)`, `T_gap(Q)` 등을 조회한다 (RFC-007).

학습 루프(RFC-010)가 제안한 프로파일은 **promotion gate**(RFC-009·RFC-010 §6.2.1) 통과 후만 배포.

5. Evidence Completeness (요약)

**규칙 본문은 RFC-007 §Evidence Obligation**, mixed·anchor는 **RFC-011**.  
요지: `decision_status == resolved`인데 필수 증거가 없으면 **downgrade**(ambiguous/failed + 적절한 `next_action`).

평가 지표는 RFC-009 **evidence completeness rate**.

6. Failure Containment (요약)

| 장치 | 문서 |
|------|------|
| Alias promotion firewall | RFC-003 §8, RFC-010 |
| Projection contamination batch | RFC-012 |
| Drift monitor | RFC-009 |
| Kill switch | 본 §7, RFC-009·010 |

7. Kill Switch (운영)

다음은 **런타임 플래그**로 즉시 비활성화 가능해야 한다 (장애·오염 시):

- alias overlay / 온라인 alias prior bump
- learning 업데이트 적용 (shadow만 허용 등)
- 신규 `threshold_profile` 라우팅 비율
- (선택) dense retrieval 전체

**관측:** 비활성화 시에도 `decision_snapshot`에 “kill switch active”류 `feature_flags` 또는 `nondeterminism_notes`를 남긴다.

7.1 Rollout protocol (shadow → canary → full)

새 모델·index·threshold profile·overlay는 기본적으로 아래 순서를 따른다.

1. **shadow** — 사용자 응답에는 영향 없이 snapshot·trace만 비교
2. **canary** — 소량 트래픽에서 RFC-009 gate·drift monitor 확인
3. **full rollout** — gate 통과 후 점진 확대

**원칙:** replay 가능성이 깨지는 변경은 shadow를 생략하지 않는다.

8. P1 연계 (세션·비용·비교)

- **SessionContext** — RFC-005; follow-up 시 anchor·constraint 상속.
- **QueryBudget** — RFC-005; adaptive pipeline(RFC-012·013과 합성).
- **comparison_query / multi-entity** — RFC-005 `QueryClass`, RFC-006 multi-entity resolve.

9. RFC 경계

본 RFC는 **운영·재현·봉인** 계약이다. 알고리즘 증명·수식 SSOT는 RFC-000·007에 둔다.

10. 체크리스트

- [ ] 모든 프로덕션 search 응답에 `decision_snapshot`이 붙는가
- [ ] Replay가 스냅샷 없이 “과거 재현”을 주장하지 않는가
- [ ] Kill switch가 문서화·대시보드·플래그와 연결되는가
- [ ] Evidence obligation 위반 시 자동 downgrade 경로가 있는가 (RFC-007)
- [ ] 새 모델·index·threshold가 shadow → canary → full 순서를 따르는가 (§7.1)

한 줄 요약

**RFC-015는 “잘 맞는 시스템”을 “망가지지 않고 재현 가능한 시스템”으로 묶는 운영 SSOT다.**
