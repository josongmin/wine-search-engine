RFC-013
Ranking Signals & Multi-objective Scoring (SOTA++)

**상위·정합 문서**

- `RFC-000: Wine Intelligence Engine Master Architecture.md` — **§6 Ranking contract·SignalSet**, **§8 Decision**(ranking은 authority 아님), **§9 Evidence**(기여는 band/signed), **§12** Cross-Encoder는 **interface**·second phase
- `RFC-012` — `HybridCandidate`·`RetrievalTrace` 입력
- `RFC-004` — 속성·constraint 정규화
- `RFC-005` — `QueryPlanV1`·`query_class`
- `RFC-008` — `component_scores`·trace → **EvidenceItem** 직렬화
- `RFC-016` — **Signal ≠ authority** — ranking score를 decision authority로 쓰지 않음

**충돌 시 RFC-000 우선.**

0. 목적

이 시스템에서 ranking은 단순 relevance 정렬이 아니다.

Entity integrity + Constraint satisfaction + Semantic relevance를 동시에 만족하는 multi-objective optimization 문제

다.

즉 한 줄:

Ranking은 “가장 비슷한 것”을 찾는 게 아니라, “가장 맞는 것”을 찾는 것이다

1. 비목표

| 하지 않음 | 담당 |
|-----------|------|
| 최종 resolve | Decision Layer (RFC-000 §8) |
| candidate 생성 | RFC-012 |
| ambiguity **최종** 판단 | RFC-006·007 / §8 |
| 자연어 explanation | RFC-008 (LLM optional) |

즉:

**Ranking은 authority가 아니라 signal producer·aggregator**다 (RFC-000 §6·§8).

**RFC-016:** ranking score는 Admission Gate를 **우회할 수 없으며**, **`resolved` 권한을 갖지 않는다**.

2. 핵심 원칙
2.1 Entity Integrity First (절대 규칙)

entity consistency가 깨지면 어떤 점수도 무의미

예:

vintage mismatch
producer mismatch
잘못된 entity type

→ 바로 패널티 또는 제거

2.2 Hard Constraint = Gate

hard constraint는 점수가 아니다.

violate → score = -∞ (또는 제거)
2.3 Score는 additive지만 의미는 계층적

수식은 합이지만, 중요도는 다르다.

우선순위:

entity integrity
hard constraint
anchor preservation (if exists)
soft constraint
semantic relevance
preference / popularity
2.4 Embedding is not enough

embedding similarity 단독으로 ranking 금지

2.5 Uncertainty는 패널티로 반영

확신이 낮은 후보는 자연스럽게 내려가야 한다.

2.6 Ranker extensibility contract

새 reranker, LTR, learned feature combiner를 넣을 수 있다. 하지만:

- 출력은 항상 **`SignalSet` / `component_scores` / traceable provenance**로 환원돼야 한다.
- 새 모델이 들어와도 **Decision status semantics**(`resolved` / `ambiguous` / `failed`)는 바뀌지 않는다.
- learned score는 `decision_confidence`가 아니며, RFC-007 Decision gate를 우회할 수 없다.
- 승격 기준은 최신 SOTA claim이 아니라 RFC-009 release gate와 RFC-015 rollout protocol이다.

4. Score 구성 (SSOT)
4.1 전체 수식 (RFC-000 §6.1 SignalSet과 정합)

이 점수는 **런타임 calibrated confidence `C`**가 아니다 — downstream에서 캘리브레이션·Decision 게이트로 합성한다.

**4.1.0 Retrieval fusion vs final ranking (RFC-012와 경계)**

`HybridCandidate.retrieval_fusion_score`(RFC-012)는 **retrieval 단계의 혼합 trace**일 뿐이다. **최종 ranking score**를 만드는 여러 소스 중 하나로만 들어가며, `Score(e)` 전체와 동일시하지 않는다 (rerank 한 덩어리로 부르지 말 것).

Score(e) ≈

  entity_integrity_score
+ anchor_similarity_score          // mixed일 때
+ hard_constraint_pass             // 0 또는 -∞ / 필터
+ soft_constraint_score
+ semantic_relevance_score
+ attribute_alignment_score
+ preference_alignment_score
+ popularity_score
+ availability_score
- uncertainty_penalty

`uncertainty_penalty`는 RFC-005 `QueryUncertainty.decision_effect`와 연동한다 — **`trace_only`**면 ranking 가중만, **`raise_threshold`/`force_clarify`/`block_resolve`**면 Decision·veto 쪽과 **역할을 나눠** 문서화한다 (RFC-007과 중복 불확실성 처리 방지).
5. 구성 요소 상세
5.1 Entity Integrity Score
S_entity_integrity =
  consistency(entity, query)

포함:

type consistency
producer match (if anchor)
vintage consistency
region sanity

실패 시:

큰 penalty 또는 제거
5.2 Anchor Similarity (Mixed Query 핵심)
S_anchor_similarity =
  f(attribute_distance, embedding_similarity)

구성:

region distance
grape similarity
body/style similarity
embedding proximity
5.3 Hard Constraint
if violated:
  score = -∞

예:

price > 100k
style mismatch
5.4 Soft Constraint
S_soft_constraint =
  Σ(weight_i * satisfaction_i)

예:

full-bodied
dry
premium
5.5 Semantic Score

dense retrieval 기반

S_semantic =
  cosine(query_embedding, doc_embedding)

주의:

단독 사용 금지
normalization 필요
5.6 Attribute Alignment
S_attribute_alignment =
  match(region, grapes, body, style)

이건 semantic보다 더 신뢰도 높음 (RFC-004 스키마)

5.7 Preference (선택)
S_preference =
  user/context alignment

예:

이전 클릭
가격대 선호
스타일 선호
5.8 Popularity
S_popularity =
  log(click + purchase)

주의:

dominance 금지
tie-breaker 수준
5.9 Availability

재고/판매 가능 여부

if unavailable:
  penalty
5.10 Uncertainty Penalty
S_uncertainty_penalty =
  ambiguity + missing info + low confidence

8.1 목표

8.2 feature 예시

8.3 label 정의 (중요)

이 시스템에서 label은 단순 클릭이 아니다.

correct resolve

8.4 training hygiene (learned ranker를 쓸 때)

- **hard negatives**는 near-miss entity, constraint violation candidate, anchor drift candidate를 포함해야 한다.
- 클릭 로그 단독을 positive label로 쓰지 말고, RFC-009 gold / adjudicated set과 함께 본다.
- train / validation / release benchmark leakage를 막기 위해 동일 query family·counterfactual 변형이 split을 넘나들지 않게 관리한다.

9. Re-ranking Layer (RFC-000 §12)

초기 Top-K 후보에 대해:

**Cross-Encoder reranker interface** 사용 가능 — 구체 모델(DeBERTa 등)에 **고정하지 않음**. Vespa **second/global phase**에 두는 패턴과 정합.

역할:

semantic 정밀도 보정 — 여전히 **단독 authority 아님**
10. Ranking Output
RankedResult {
  entity_id: EntityId

  final_score: float              // fusion 이후 — **calibrated C와 동일 스케일 아님**

  component_scores: {
    entity_integrity: float
    anchor_similarity?: float
    semantic: float
    constraint: float
    ...
  }
}

**RFC-008:** `component_scores`·출처는 **EvidenceItem**(`type`, `source`, `contribution`, `strength`, `provenance`)으로 옮길 때 **정확한 % 분해를 주장하지 말 것** (RFC-000 §9.3).

11. Failure Modes
11.1 Semantic Dominance

12. Metrics

**NDCG·MRR@K** — rerank/리스트 품질 **보조**만 (RFC-000 §10, RFC-009).

Constraint Satisfaction Rate
Anchor Preservation Rate
Ranking Stability
Feature / evidence 일관성 (과도한 % attribution 금지)

**Decision Utility**·wrong-resolve (RFC-000 §10.7)를 **대체하지 못함**.

15. 체크리스트 (리뷰용)
